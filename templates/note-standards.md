# 筆記寫作規範範本（給醫療工作者的知識庫）

> **這份是範本，要改寫後才用。** 它從作者知識庫的寫筆記規則（`reference/vault_neo/02_EM/EM_Evidence_Standards.md`
> 與作者的 deepnote 程序）抽出、去掉急診專屬的部分，改寫成醫師、護理師、藥師、治療師、醫檢師等都能用的版本。
>
> **給 AI**：和使用者一起改寫後，存成他資料夾裡的 `note-standards.md`，並在他的 `AGENTS.md` 加一行
> 「寫或改 `wiki/` 筆記前先讀 `note-standards.md`」。第一版只放 **Part 1**；Part 2 等他遇到對應問題再加。
> 改寫時要問的事見文末「改寫清單」。

---

## Part 1：起手必備

### 1.1 知識從哪裡來

1. 筆記內容**只能來自 `raw/` 的原文**（或使用者明確提供的素材）。原文沒寫的，不用訓練資料補；
   覆蓋不足就寫「原文未深入此主題」或省略。
2. **數字逐字對齊原文**：劑量、cutoff、CI、RR、p 值、樣本數、年份不四捨五入、不換單位求通順。
3. **觀點標名**：作者、講者、來賓的個人意見要寫出是誰說的（「Smith 認為…」），不包裝成客觀事實。
4. 每篇筆記在 frontmatter 的 `source_md` 指向它的原文檔（wikilink），讓任何一句都能回去核對。

### 1.2 怎麼讀原文

- 原文不長（約 4 萬字元以內）就整份讀完再寫。
- 原文很長（整本書、整個章節合輯）時，**先定位再讀**：用章節標題或主題關鍵字找出本篇對應的段落，
  從起點讀到下一個章節邊界，不夠就分次續讀。
- **禁止只讀檔頭前 N 字就動筆**：後段內容會整段落在視窗外，寫出來的筆記看起來完整，其實沒有根據。
  定位不到就停下來回報，不要拿檔頭充數。
- 讀了哪一段，記在 frontmatter：`source_span: "L120-L480"`（行號範圍；整份讀完寫 `full`）。

### 1.3 檔名

| 素材 | 檔名 | 例 |
|---|---|---|
| 期刊文獻、review、guideline | `第一作者姓Year_Keyword.md` | `Smith2021_SepsisFluids.md` |
| 教科書章節 | `書名縮寫_Ch{N}_Keyword.md` | `Harrison_Ch45_Hyponatremia.md` |
| blog／podcast | `作者或網站Year_Keyword.md` | `EMCases2024_SyncopeRisk.md` |
| 學會或機構文件 | `機構Year_Keyword.md` | `SSC2021_SepsisGuideline.md` |

Keyword 用 1–3 個英文主題詞、CamelCase、不加底線。同一概念沿用資料夾裡既有的拼法，不造變體。

### 1.4 Frontmatter

```yaml
---
title: <原文標題>
type: note
category: <study|review|guideline|textbook|blog|case>
source_md: "[[raw/<原文檔名>]]"
source_span: "<L起-L迄 或 full>"
tags: [tag1, tag2]
created: <YYYY-MM-DD>
updated: <YYYY-MM-DD>
---
```

- `tags` 一律寫成一行陣列、不加引號；醫學縮寫大寫（ECG、COPD、DKA）。
- 下 tag 前先看資料夾裡 2 篇既有筆記用什麼名稱，有同義的就沿用（不要一篇 `CO-poisoning`、一篇 `carbon-monoxide`）。
- frontmatter 不可巢狀（Obsidian 會顯示異常）；需要分項就攤平成 `pico_P`、`pico_I` 這種欄位。
- 文獻類可加：`study_design`、`first_author`、`year`、`journal`、`pmid`、`doi`。

### 1.5 各類筆記的必要段落

| category | 必要段落 |
|---|---|
| study（原始研究） | `## 研究背景`、`## 研究設計`（族群、介入、對照、主要結果指標）、`## 關鍵數據`、`## 限制`、`## 實務啟示`、`## 相關筆記` |
| review／guideline | `## 主要建議`（保留建議強度與證據等級）、`## 實務啟示`、`## 相關筆記` |
| textbook 章節 | `## 章節定位`、`## 核心概念`、`## 關鍵表格`、`## 關鍵圖表與流程`、`## 實務要點`、`## 相關筆記` |
| blog／podcast | `## 核心論點`、`## 內容摘要`、`## 實務啟示`、`## 相關筆記` |
| case | `## 案例摘要`、`## 鑑別或判斷過程`、`## 學習重點`、`## 相關筆記` |

- **實務啟示**是整合後寫給使用者自己工作場景的重點（見文末改寫清單），不是逐段翻譯原文。
- 原文沒有的內容不硬寫：例如沒有音檔就沒有時間戳，沒有圖就不寫圖表段；空段落寫「原文無」。
- 內文用使用者的語言；藥名、量表、試驗名、專有名詞保留原文。

### 1.6 連結

- 文末 `## 相關筆記` 列 2–5 篇最相關的既有筆記：`[[檔名]]`，不加 `.md`。
- **只連結確定存在的檔案**。連之前先確認檔案在、主題對得上，不從檔名猜內容；不存在的不寫。
- 同一本書的章節筆記，第一條連回該書的總覽頁（若有）。

### 1.7 顯示語法

- `---` 只用在 frontmatter 上下；正文要分隔線改用 `***`。
- Markdown 表格每一行以 `|` 開頭、以 `|` 結尾。
- 筆記檔放 `wiki/`，不放 `raw/` 或 `originals/`。

### 1.8 個資

- case 筆記與任何臨床紀錄：不寫姓名、病歷號、生日、地址、照片、可辨識的罕見細節組合；使用者放進來的素材若含這些，先提醒去識別化再寫。

### 1.9 寫完自查（封閉式清單，逐條回答是／否）

1. 檔案在 `wiki/`，檔名符合 1.3？
2. frontmatter 有 `title`、`type`、`category`、`source_md`、`tags`、`created`、`updated`，且沒有留 `<佔位符>`？
3. `tags` 是一行陣列？
4. 1.5 該類的必要段落都在？
5. 每個 wikilink 指向的檔案都存在？至少 2 個？
6. 隨機抽 3 個數字回原文比對，完全一致？
7. 正文沒有用 `---` 當分隔線？

全部「是」才算完成。只檢查清單上的項目，不臨場發明新規則來判不合格。

## Part 2：遇到問題再加

| 遇到的問題 | 加這條 |
|---|---|
| 重寫舊筆記後，自己手加的註記不見了 | **2.1 重寫不覆蓋** |
| 多篇來源對同一處置說法不同，筆記平鋪並列 | **2.2 跨來源取捨** |
| 筆記數量變多，想讓另一個 AI 幫忙檢查 | **2.3 產出者 ≠ 檢查者** |

### 2.1 重寫不覆蓋

重寫既有筆記時：

1. 先把舊筆記複製一份暫存。
2. **不看舊筆記**，只依原文重寫（先看舊稿會傾向照抄舊稿的說法，而不是回原文）。
3. 寫完再逐點比對舊稿：新稿已涵蓋的丟掉；舊稿有、原文也有的補回；
   舊稿有、原文沒有的（使用者手寫的心得、跨筆記觀察、連結）**一律保留**，放回新結構對應的段落並標明「既有註記」。
4. 不要整段貼到檔尾；保留原 `created`，更新 `updated`，tags 取聯集。回報保留了幾條，0 條也要說。

### 2.2 跨來源取捨

一篇筆記整合 3 個以上來源、談同一個處置時，不平鋪並列：

- 證據預設排序：多中心 RCT／系統性回顧 → 學會指引（多學會聯合高於單一學會）→ 單一專家更新（blog、podcast）
  → 教科書（新版優於舊版）→ 個人意見。族群差異大、設計缺陷明顯時可降權，並寫明理由。
- 分「主推／備選／已被取代或限特定情境」三層；被取代的寫出被誰取代、取代範圍。
- 舊說法不刪：知識怎麼演變本身有價值。時序以**發表年**為準，不是入庫日。
- 主推研究的外推限制（族群、open-label、無直接比較）要寫，不只列正面結果。

### 2.3 產出者 ≠ 檢查者

寫筆記的 AI 和檢查的 AI 分開：檢查者只拿到筆記、原文與 1.9 清單，不給寫的人的推理過程。
檢查者判不合格時，先確認它引用的規則真的在本檔；查無此規則就當作合格。

## 改寫清單（AI 和使用者一起過一次）

1. **職業與工作場景**：醫師（哪一科）、護理師（病房／加護／門診）、藥師、物理／職能／呼吸治療師、醫檢師、營養師……
   「實務啟示」改成他的場景會用的角度，例如：
   - 護理：評估重點、給藥與監測、衛教要點、何時通報醫師
   - 藥師：劑量調整（腎、肝功能）、交互作用、配伍與給藥途徑
   - 治療師：功能評估、介入參數、禁忌與停止條件
2. **素材種類**：他最常讀什麼？用不到的類別從 1.5 刪掉，缺的類別照同樣格式補一列。
3. **語言**：內文用什麼語言、專有名詞保留到什麼程度。
4. **檔名與 tag**：1.3 的範例換成他領域的真實例子。
5. **紅線**：他的機構對資料有什麼規定，寫進 1.8。

改完的版本控制在 80 行內。之後每加一條，都要對應一個實際發生過的問題。
